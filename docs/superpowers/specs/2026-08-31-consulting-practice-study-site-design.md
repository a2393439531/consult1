# 2026 咨询工程师《现代咨询方法与实务》复习网站设计

## 1. 目标与范围

将指定资料目录中的 60 份 PDF（共 980 页）整理成面向备考的静态交互题库，并发布到 GitHub Pages。视频及其他非文字类文件不处理。用户已确认拥有整理并公开发布这些资料的授权。

网站提供两条主要学习路径：

1. 按教材 11 章复习，默认隐藏答案，作答后展开解析。
2. 按原试卷完成整卷模考，支持计时、草稿、交卷后查看答案和自评。

复习记录只保存在当前浏览器，不引入账号、服务器或云端同步。

## 2. 内容处理

### 2.1 数据来源

- 输入目录：`E:\BaiduNetdiskDownload\2026年咨询【实务】SVIP\2026年咨询【实务】SVIP\03-习题精析✿实战特训✿模考通关`
- 纳入所有 PDF，包括章节题、强化母题、历年真题、模考卷和查缺补漏资料。
- 忽略视频文件，即使视频与 PDF 同名，也只处理 PDF 讲义。
- 每条内容保留来源资料、机构/教师、年份、PDF 文件名及页码范围，便于追溯。

### 2.2 提取与校对

先用 MarkItDown 批量转为 Markdown；对编码错误、文本层缺失、表格错位或公式破损的页面，依次采用 `pdftotext -layout`、局部 OCR 和原页图像核对。正文中的广告、水印、联系方式、页眉页脚和重复标题不进入题库。

需要人工式规则校对的重点包括：

- 金额、百分比、正负号和小数点；
- 财务与经济分析公式；
- SWOT、波士顿矩阵、逻辑框架矩阵等图表；
- 跨页题干、表格和答案；
- 题目中要求列出计算过程的步骤。

### 2.3 章节归类与去重

以 11 章教材体系为主分类，知识主题为二级分类。真题、综合讲义和模考题根据考查方法归入对应章节，同时保留原试卷映射。

去重分两层进行：

1. 规范化题干后生成内容指纹，识别文字一致或仅水印不同的重复题。
2. 对高度相似但解析不同的题，以题干完整、计算过程详细的版本为主，合并其他来源的有效补充。

同一案例下的多个小问保持为一组，不拆成失去背景的孤立题。若一题跨多个章节，以主要考点为主章节，其他考点作为关联标签。

## 3. 题库数据模型

每个案例题包含：

- 稳定 ID、标题、章节、知识点、题型和难度；
- 来源、年份、试卷 ID、原 PDF 和页码；
- 背景材料、结构化表格、必要图示；
- 若干小问；
- 每个小问的参考答案、计算步骤、评分关键词、易错点；
- 搜索关键词及关联章节。

模考试卷包含：试卷信息、建议时长、题目顺序、总题数及题库案例 ID 列表。章节题库和模考共享同一题目实体，避免维护两份答案。

构建前使用 JSON Schema/TypeScript 校验数据，阻止缺失题干、答案、章节或来源的记录进入网站。

## 4. 页面与交互

### 4.1 首页

首页突出“继续复习”，展示 11 章学习进度、待复习题数、收藏题数和可用模考试卷。用户可从上次位置继续，也可进入章节目录、全站搜索或整卷模考。

视觉方向采用安静、专注的纸张式阅读界面：米白背景、深墨色正文、沉稳蓝绿色作为操作色，橙红色只用于待复习与易错提醒。中文正文以系统无衬线字体保证屏幕清晰度，标题使用具有书卷感的中文字体回退栈。不使用无关装饰图片。

### 4.2 章节页

左侧为章节与知识点导航，主区显示题目列表，顶部提供来源、年份、题型、难度和状态筛选。移动端将侧栏折叠为抽屉。

题卡先显示背景、表格和问题，答案默认隐藏。用户可以：

- 在草稿框中输入自己的答案；
- 展开标准答案和逐步解析；
- 按“已掌握 / 待复习”自评；
- 收藏题目；
- 跳到上一题或下一题；
- 查看来源和原页码。

### 4.3 搜索与错题复习

全站搜索覆盖题干、答案、知识点和来源。搜索结果可以继续按章节、年份和题型筛选。错题页聚合“待复习”和收藏内容，并支持只看未掌握题目。

### 4.4 整卷模考

开始前展示试卷信息和建议时长。开始后显示计时器、题号导航、作答状态和草稿输入；答案不可提前显示。交卷后停止计时，逐题展示参考答案，用户对每个小问自评，并生成已作答、待复习和完成用时汇总。刷新页面后从浏览器本地恢复未交卷试卷。

主观题不自动评分，也不展示伪精确分数。

## 5. 技术架构

- React + TypeScript + Vite 构建单页静态网站。
- React Router 使用 HashRouter，避免 GitHub Pages 子路径刷新产生 404。
- 题库内容保存为构建时加载的分片 JSON；按章节和试卷拆分，避免首页加载全部内容。
- Fuse.js 提供纯前端中文模糊搜索。
- Zustand（带 persist 中间件）管理收藏、掌握状态、草稿、最近位置和模考会话，底层使用 `localStorage`。
- KaTeX 渲染公式；普通表格使用语义化 HTML，复杂图表重绘为可访问的 SVG 或表格。
- 网站为纯静态资源，不包含用户隐私数据、密钥或服务端接口。

内容处理脚本与网站源代码分离：脚本负责提取、清洗、去重、校验和生成 JSON；前端只消费稳定的数据模型。

## 6. 错误处理

- 内容构建遇到无法解析的 PDF 页面时记录文件、页码和原因，不静默丢弃。
- 数据校验失败时构建立即失败，并输出具体题目 ID 和字段。
- 浏览器本地数据损坏时回退为空状态，不影响阅读题库；提供“清除本机学习记录”入口并要求二次确认。
- 模考刷新或意外关闭后恢复计时起点、草稿和题目状态。
- 网站对 JavaScript 加载失败提供基础提示和刷新建议。

## 7. 可访问性与响应式

- 所有交互可用键盘操作并具有清晰焦点样式。
- 答案展开、收藏、自评和计时状态有文字标签，不只依赖颜色。
- 正文行宽控制在适合长时间阅读的范围；表格在窄屏可横向滚动。
- 支持桌面、平板和手机；移动端优先保证读题、草稿和答案展开体验。
- 尊重 `prefers-reduced-motion`，仅使用短暂、非必要的过渡动画。

## 8. 测试与验收

### 8.1 内容验收

- 60 份 PDF 均出现在处理清单中，未处理项必须有明确原因。
- 每一章至少抽查不同来源的题目；所有计算类题目校对关键数字、公式和结果。
- 每份模考试卷核对题目顺序、题目数量和答案映射。
- 去重报告列出合并题及其来源，不删除唯一解析信息。

### 8.2 软件验收

- 单元测试覆盖数据校验、筛选、搜索索引、学习状态和模考状态机。
- 组件测试覆盖答案默认隐藏、展开、自评、收藏、草稿恢复和交卷流程。
- 生产构建成功，GitHub Pages 子路径访问和刷新可用。
- 使用自动化浏览器检查桌面和移动端的核心流程、键盘操作及控制台错误。

## 9. 发布

创建独立 GitHub 仓库，源码使用默认分支，GitHub Actions 在每次推送后执行测试、构建并发布 `dist` 到 GitHub Pages。仓库不包含原始 PDF，只包含经过授权整理的结构化题库内容、处理报告和网站源代码。

最终交付包括公开网站地址、GitHub 仓库地址、内容覆盖报告和本地数据清除说明。
